# TelTel integration contract

Source: [TelTel API documentation](https://apidoc.teltel.io/). The page references the [OpenAPI root](https://api.teltel.io/v2/api.user.0d9ae995324f03f254d3da8d963d46b2.json); relative schema files were resolved and retained in `docs/provider/teltel.resolved.json`. The document's info version is 3.0.0, while its documented HTTP base is `https://api.teltel.io/v2`.

Authentication always uses `X-API-KEY`. Credentials are never placed in URLs, browser state, or logs. Redirects are rejected; the client cannot target arbitrary hosts.

The connected project is in **live mode** with one TelTel account and an owner-confirmed EUR currency. Balance, users, devices, DIDs, calls, and status definitions have been retrieved successfully using genuine credentials. The previous synthetic dataset and sample authentication identities have been permanently removed; both administrator accounts remain.

## Synchronization

- A durable PostgreSQL queue uses `FOR UPDATE SKIP LOCKED`, 90-second leases, heartbeat renewal, deduplication of queued resources, and exponential retry delays.
- Successful resources are recorded independently, so a failure does not verify another resource. The first provider must retrieve balance, users, devices, DIDs, and calls before another provider can be created.
- GET calls retry timeouts, throttling, and 5xx responses with a bounded delay. Mutation requests are never blindly retried. An ambiguous callback outcome keeps its idempotency key pending for reconciliation.
- Calls currently synchronize a rolling **seven-day** window with UTC query parameters and overlap. This is not a complete historical archive import. A configurable backfill service and operational reconciliation remain outstanding.
- The DID schema limits `offset` to 500 and `limit` to 500. The implementation stops with `PAGINATION_LIMIT` rather than claiming a complete import beyond that documented limit.
- No missing upstream resource is automatically deleted, released, or reassigned.
- Client call ownership follows explicit, account-scoped number assignments within their effective dates. DID matching uses outbound `caller.cid` and inbound `caller.dnid`, falling back to the inbound callee number only when the original DID is unavailable. This separates clients even when they share a TelTel company user and SIP device. Conflicting or ambiguous ownership creates an exception and cannot be charged.
- TelTel account emails belong to company accounts; client login emails are independent. A provider account can be associated with its company, and unassigned calls remain company records with no client owner. `link_provider_user` is retained for legacy company-staff mappings and rejects automatic whole-account links to client logins.
- `assign_number_client` is the privileged manual assignment operation. It validates company/client membership, closes the previous allocation, disables old callback permissions, and preserves existing call ownership. Company inventory includes provider-owned numbers before a client is assigned. Clients cannot assign themselves numbers or read other clients' calls.
- There is no documented final-billing marker. Under the owner's client billing policy, new completed answered outbound Germany calls are rated after a 60-second settling interval using `handle_sec` actual talk time, not `waiting_sec` or wholesale cost. Provider corrections append retail debit/refund differences using the captured rate. Pre-activation history is excluded; other destinations and currency mismatches remain unpriced/reviewable. Legacy company/staff calls still require explicit rating.

## Callback prerequisites

The backend requires an active company and membership, callback permission, a verified `caller_id_permissions` record, an authorized employee/device/allocation pairing on the same upstream account, a current allocation, allowed calling-country prefix, an enabled account, sufficient prepaid balance, and a request rate limit. Identity provisioning and upstream caller-ID verification still require an operator workflow; until those records are verified, the dialer correctly displays no available calling identity.

Prepaid checks restrict new platform callback requests. They do not authorize direct SIP traffic at the provider and do not guarantee immediate interruption of an existing call.
